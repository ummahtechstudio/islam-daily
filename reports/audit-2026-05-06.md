## Critical Issues

### C-1 — `adhan.mp3` is a 183-byte placeholder, not a real audio file

- **File / line:** `assets/audio/adhan.mp3` (183 bytes); referenced from `app.json:71`, `src/services/notificationsService.ts:147`, `src/services/notificationsService.ts:182`. Marked as placeholder in `assets/audio/README.md:13–19`.
- **Description:** The `expo-notifications` plugin bundles this file as the prayer-time sound. With an empty placeholder shipped to production, prayer notifications fall back to the default Android/iOS notification tone — the central "adhan reminder" feature silently degrades. App-store reviewers and users will notice immediately on the first prayer-time fire.
- **Fix:** Drop in a 10–15 s royalty-free adhan clip per the steps already documented in `assets/audio/README.md`, then `npx expo prebuild --clean` and rebuild via EAS preview before submitting to Play Store.
- **Priority:** Critical

### C-2 — Hardcoded HadithAPI key embedded in client bundle

- **File / line:** `src/services/api.ts:6`, `src/store/index.ts:35`
  ```ts
  const HADITH_API_KEY = '$2y$10$OVeHKOYpQOnG3P3gE8r657qTqbRhRIJSNStLz5GdzOAioMbhMG';
  ```
- **Description:** This single key ships in every install, is trivially extractable from the APK/AAB, and is shared across all users. If hadithapi.com rate-limits or revokes it, the in-app hadith path that depends on it breaks for every user simultaneously. The newer R2 + MMKV hadith pipeline (`src/services/hadithCache.ts`) does *not* depend on this, so the legacy `fetchHadiths` path is the actual risk surface.
- **Fix:** Grep `fetchHadiths` callers across `app/` and `src/screens/`. If zero remain on shipping screens, delete `fetchHadiths` from `api.ts` and the `hadithApiKey` field from `store/index.ts`. If any caller remains, route it through the R2 cache and then delete.
- **Priority:** Critical

### C-3 — Quran ayah audio leaks across navigation

- **File / line:** `app/quran/[id].tsx` — `soundRef` is created inside `playAyah()` but no `useEffect` cleanup unloads the sound on unmount.
- **Description:** Navigating away mid-playback leaves the `Audio.Sound` resource alive. Rapid surah-switching can stack multiple instances, exhaust the device's audio handle pool, or keep audio playing in the background after the user has left the screen.
- **Fix:** Add an unmount cleanup near the existing audio refs:
  ```tsx
  useEffect(() => () => {
    soundRef.current?.unloadAsync().catch(() => {});
  }, []);
  ```
- **Priority:** Critical

### C-4 — Icon-only buttons missing `accessibilityLabel`

- **Files / lines (sample):**
  - `src/components/tasbeeh/TasbeehCounterView.tsx:341` (list icon)
  - `app/search.tsx:70–71` (back arrow)
  - `app/search.tsx:93–95` (clear-input X)
  - `src/components/quran/ReciteTab.tsx:341–342` (close)
- **Description:** Each is a `TouchableOpacity` whose only child is an `Ionicons` element with no text and no `accessibilityLabel`. Play Store's accessibility scan flags this; TalkBack users cannot operate the tasbeeh, search, or recitation surfaces. Apps with religious / community audiences are routinely held to this rule.
- **Fix:** Add `accessibilityLabel` and `accessibilityRole="button"` to each — e.g. `accessibilityLabel="Back"`, `"Clear search"`, `"Open tasbeeh list"`, `"Close"`. ~5-minute change.
- **Priority:** Critical

## Important Issues

### I-1 — RLS policies commented out for `user_bookmarks`, `prayer_streaks`, `hifz_progress`

- **File / line:** `scripts/supabase_schema.sql:111–130`. Tables exist; `enable row level security` and the matching `create policy` statements are commented out.
- **Description:** The shipping client uses local AsyncStorage for these features (verified — no Supabase reads/writes for them in `src/`), so users aren't exposed. But the tables sit on the public Supabase project with the publishable anon key able to read/write them. Anyone scraping the APK can dump or pollute these tables.
- **Fix:** Either drop the unused tables (preferred — they're dead weight), or run the commented-out `enable row level security` + per-user policy block.
- **Priority:** Important

### I-2 — `.env` workspace hygiene + `.env.example` exposes real account ID

- **Fix:** Replace `.env.example` values with placeholders (e.g. `R2_ACCOUNT_ID=your_account_id_here`). Clean up the malformed `.env`. If the R2 secret has ever been pasted into screenshots, chats, or PRs, rotate it.

### I-3 — Audio Library has 41 placeholder TODO URLs

### I-4 — `ErrorView` is largely unused

- **Priority:** Important

### I-5 — `setTimeout` in tasbeeh round-celebration without cleanup

- **Fix:** Capture the handle in a ref and clear it in the effect cleanup; or wrap in `useEffect` with cleanup.

### I-6 — Privacy-policy URL needs verification before submission

## Recommendations

### Top 3 must-fix before Play Store submission

1. **Replace `adhan.mp3` with a real 10–15 s clip and rebuild** (C-1). Without this, prayer notifications silently degrade.
2. **Add `accessibilityLabel` to the 4+ icon-only buttons** in `TasbeehCounterView.tsx`, `search.tsx`, `ReciteTab.tsx` (C-4). ~5 minutes; avoids accessibility-policy rejection.
3. **Verify the privacy-policy URL** at `app/settings.tsx:92` is live and Play-Store-compliant (I-6). One manual check.

### Defer to v1.1

- Audio-library URL backfill (I-3) — gate broken entries behind a flag for now.
- ErrorView consolidation across location screens (I-4).
- RLS cleanup on unused Supabase tables (I-1) — drop or enable.
- `expo-av` → `expo-audio`/`expo-video` migration (M-1).
- `hifz-tracker` empty state (M-4).
- `daily_knowledge` final decision (M-7).

### Architectural concerns for long-term maintenance

- **Two parallel data paths for hadith.** `src/services/api.ts` (legacy hadithapi.com w/ hardcoded key) and `src/services/hadithCache.ts` (R2 + MMKV). Pick one and delete the other before more features pile on.
- **Quran fetched from Supabase, hadith fetched from R2.** Intentional for size/cost reasons, but document the rationale somewhere central — otherwise the next contributor will move them and break offline.
- **Prayer-time auto-detection covers ~10 countries** (`src/services/prayerTimesService.ts:113–125`); everywhere else falls back to MWL. Fine, but call this out in the prayer-times-settings UI so users in, e.g., Indonesia know to pick a method manually.

### Categories where audit was incomplete

- **R2 hadith data integrity at runtime.** Verified the public CDN URL constants are correct (`pub-3f76e9c4da264c6ba85283d8af8108a0.r2.dev` in `src/services/hadiths.ts:12`, `src/services/books.ts:4`) but did not actually fetch and parse the live JSON files — that requires network access not available to this audit.
- **Numeric prayer-time accuracy.** Confirmed the `adhan` package and method-per-country mapping. Did not numerically verify times for Karachi/Dubai/London against an external authority.
- **Privacy-policy contents.** Did not fetch the GitHub Pages URL to confirm the page is live and policy-compliant — flagged as I-6.
