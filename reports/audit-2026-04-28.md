## Important Issues (should fix before APK)

### I-1. Audio library has 43 placeholder URLs awaiting archive.org replacements
- **File:** `src/constants/audioLibraryData.ts`
- **Lines:** 88, 152, 163, 174, 185, 196, 210, 221, 232, 243, 254, 268, 279, 290, 301, 312, 323, 334, 345, 356, 367, 378, 389, 403, 414, 425, 436, 447, 458, 469, 480, 494, 505, 516, 527, 541, 552, 563, 574, 585, 596 (43 entries)
- **Marker:** `// TODO: Replace with [official/working] [service] URL from archive.org`
- **Description:** Each entry has a fallback URL but is flagged as not-yet-vetted. Users will hit broken playback if any of these archive.org URLs are dead or point to wrong content.
- **Suggested fix:** Run `scripts/verify-book-links.ts`-style verification against each URL; replace dead links; remove TODOs once verified.
- **Priority:** Important

### I-2. "Coming Soon" features visible in shipping UI
Found 6 user-visible "Coming Soon" markers. These ship as-is unless gated:
- `src/screens/DownloadScreen.tsx:114` — `unavailable: 'Islamic Books pack coming soon'`
- `src/screens/DownloadScreen.tsx:275` — `'This pack is coming soon!'`
- `app/islamic-books.tsx:139` — UI badge `Coming Soon`
- `app/settings.tsx:188` — `'Coming Soon', 'Light and Auto themes will be available in a future update.'`
- `app/settings.tsx:344` — UI badge `Coming Soon`
- `app/settings.tsx:688` — `'More translations coming soon'`
- **Suggested fix:** Decide per-item: (a) ship the feature, (b) hide the entry, or (c) accept the "Coming Soon" badge as an honest user signal. Themes + Islamic Books pack are the two most user-facing.
- **Priority:** Important (UX expectation; not a bug)

### I-3. Daily Knowledge & Islamic Tips lack structured citations
- **Files:** `assets/daily_knowledge.json` (52 entries), `assets/islamic_tips.json` (30 entries)
- **Description:** These are the only two religious-content files without a structured `reference`/`source` field. Some `islamic_tips` entries cite a collection inline (e.g. "(Bukhari)") inside the `tip` text; others don't. `daily_knowledge` entries cite nothing.
- **Why it matters:** This is a religious app — users should be able to verify claims. Citation accuracy is part of trust.
- **Suggested fix:** Add a `reference` field to each entry (parallel to `hisnul_muslim.json`'s structure). Where citation is general advice with no specific narration, mark explicitly (e.g. `"reference": "General Islamic teaching"`).
- **Priority:** Important

### I-4. Async / Promise rejections without handlers
The error-handling audit flagged ~14 sites. Most prominent:
- `app/(tabs)/quran.tsx:261` — `AsyncStorage.setItem(LAST_PAGE_KEY, ...)` in `onViewableItemsChanged` with **no try/catch / no .catch**. Fires on every scroll; will produce unhandled-rejection warnings if storage write fails.
- `app/qibla.tsx:102-103` — `Magnetometer.isAvailableAsync().then(...)` no error handler.
- `src/hooks/useQuran.ts:33-35` — `AsyncStorage.getItem().then(...)` no catch.
- `app/settings.tsx:121-126` — multiple `AsyncStorage.getItem().then(...)` without catch.
- `app/custom-adhan.tsx:43-45`, `app/prayer-streak.tsx:59-61`, `app/(tabs)/quran.tsx:216-218, 541-543`, `app/_layout.tsx:90-92`, `app/hadith.tsx:149-150`, `app/(tabs)/more.tsx:131`, `components/CardActionsRow.tsx:33-35` — same pattern.
- `app/mosque-finder.tsx:66-71` — `await response.json()` without checking `response.ok` first; malformed/HTTP-error responses will throw.
- **Suggested fix:** Wrap `.then()` chains with `.catch(err => console.warn('[scope]', err))`, or migrate to `try/await`. Validate `response.ok` before `.json()` in mosque-finder + ramadan.
- **Priority:** Important

### I-5. `assets/names_of_allah.json` last entry has wrong `number`
- **File:** `assets/names_of_allah.json` (entry index 100, line ~101)
- **Description:** The 100th entry has `"number": 99` (should be `100`). Cosmetic but visible if the UI shows the index.
- **Suggested fix:** Change `99` → `100` on the final entry.
- **Priority:** Important (data correctness; one-character fix)

### I-6. `app.json` Android permissions duplicated
- **File:** `app.json:38-47`
- **Description:** `ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION` appear twice — once in short form (lines 39–40) and once in full form `android.permission.ACCESS_*` (lines 45–46). Harmless but messy and may surface in Play Console permission diff.
- **Suggested fix:** Keep one form (short form is conventional in Expo).
- **Priority:** Important (cleanliness for Play Store submission)

### I-7. README is generic Expo boilerplate
- **File:** `README.md`
- **Description:** Default Expo template content. No project description, no build/release instructions, no privacy-policy link, no app-store URLs.
- **Suggested fix:** Replace with: app description, features, build steps, privacy policy URL (legal URLs already on GitHub Pages per phase F.1), support contact.
- **Priority:** Important (Play Store may reject if support URL missing; users land on this if they hit GitHub).

## Nice-to-Have (can defer to v1.1)

### N-1. Hardcoded color literals — 308 instances across 24 files
- **Theme system:** `src/constants/colors.ts` (primary) and `constants/theme.ts` (legacy) — well-defined, but underused.
- **Top offenders:** `app/settings.tsx` (54), `app/(tabs)/more.tsx` (30), `app/(tabs)/index.tsx` (28), `app/(tabs)/quran.tsx` (23), `app/hadith.tsx` (20), `app/islamic-books.tsx` (19), `app/halal-finder.tsx` (19), `app/quran/[id].tsx` (18).
- **Why nice-to-have:** Doesn't affect launch — colors render fine. But theme drift makes future palette tweaks painful (especially dark-mode polish).
- **Suggested fix:** Migrate inline hex to `Colors.light.*` / `Colors.dark.*` via search & replace. Defer to v1.1.
- **Priority:** Nice-to-have

### N-2. Synchronous JSON imports at module init
- `app/(tabs)/dua.tsx:23-25` — `require('../../assets/hisnul_muslim.json')` (72 KB) + `require('../../assets/dhikr.json')` (27 KB)
- `app/(tabs)/index.tsx:32` — `import KNOWLEDGE_DATA from '../../assets/daily_knowledge.json'` (76 KB)
- `app/names.tsx:21` — `import namesJson from '../assets/names_of_allah.json'` (44 KB)
- `src/services/downloadService.ts:301, 374` — fallback `require()` of `hadiths.json` + `names_of_allah.json`
- **Description:** Total ~220 KB loaded at module init. Not bundle-killers, but slows cold start by a few hundred ms.
- **Suggested fix:** Lazy-load on screen mount via dynamic import. Or accept — the cost is small.
- **Priority:** Nice-to-have

### N-3. Modal `Pressable` containers without `e.stopPropagation()`
- `app/quran/[id].tsx:678` — reciter picker sheet
- `app/quran/[id].tsx:712` — recite settings sheet
- `app/quran/[id].tsx:785` — word popup
- **Description:** Sheets are wrapped in modals whose backdrop dismisses on tap. The inner sheet `Pressable` has no `onPress`, so taps inside the sheet bubble to the backdrop and may close the modal.
- **Suggested fix:** Add `onPress={(e) => e.stopPropagation?.()}` (or migrate sheets to `View`).
- **Priority:** Nice-to-have (test in QA — may already work as expected if backdrop uses `pointerEvents`).
